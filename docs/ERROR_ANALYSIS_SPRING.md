# Error analysis: Spring test (phase 2) - L3

> ตัวเลขทุกตัวสร้างโดย `error_analysis_spring.py` จาก output ที่บันทึกไว้เท่านั้น (`runs/*/spring_last*/per_pixel.npz`, `metrics.json`, `floors_out/spring`, cache GT `data/spring_hex`); ไม่มีการรันโมเดลบน Spring/Sintel อีก. ทุกข้อสรุปเป็น **L3 (exploratory)** ยกเว้นตัวชี้วัด L1 ที่ทวนซ้ำ (EPE รวม, depth aligned RMSE). ตารางอยู่ที่ `results/error_analysis_spring/`, ภาพ `docs/figs/sp_*.png` (สี: connectome=amber, null=coral, deep learning=teal, วิธีของเรา=violet, ablation=violet อ่อน/ลาย, floors=เทา).
> ข้อจำกัดของข้อมูล: `per_pixel.npz` เก็บเฉพาะ error รายเฮกซัล ไม่เก็บค่าทำนาย จึง **ประมาณ** ความเร็วที่ทำนายจาก (|GT|, EPE, angular error) ด้วยการแก้สมการต่อเฮกซัล (ใช้ทุก 4 เฟรม). ทดสอบกับข้อมูลสังเคราะห์ (float16 เหมือนไฟล์จริง): อัตราส่วนเฉลี่ยประมาณ/จริง = 1.02 (ความเร็วทำนายสัดส่วนกับ GT) และ 1.16 (lognormal; decile บนสุดเอนเอียง 2.2x) จึงให้ช่วงขอบเขตตรงๆ ควบคู่ (|EPE-|GT|| ถึง EPE+|GT|). ตรวจแล้ว: EPE/depth จาก per-pixel ตรง metrics.json (ต่างสูงสุด 7.7e-07), GT speed ตรง cache, valid mask เหมือนกันทุก run. M1 seed 1 มี 4793 เฮกซัลที่ EPE เกิน float16 (ตั้งเป็น 65504 = ขอบล่าง) จึงใช้ EPE ระดับ clip จาก metrics.json แทนสำหรับตารางที่เป็น EPE รวม/ต่อ sequence.

บริบท: Spring มี 8 sequence (24 clip, 6069 ก้าว 50 Hz), GT ช้า: zero-flow EPE = 0.4997 (= ความเร็ว GT เฉลี่ย 0.4997), LK = 0.4655. ความเร็ว GT กระจุกที่ sequence 0033 (7% ของเฮกซัล แต่ 47% ของ zero-flow EPE รวม) และ 0005 (21%). แยก M1 เป็น "M1 seeds 0,2" กับ "M1 seed 1" เสมอ.

1. มีเพียง **8 sequence** (24 clip ที่ไม่อิสระ: 3 vertical split ต่อ sequence) และ 3 seed; sequence 0033 และ 0005 ครอบงำ EPE รวม; ผลต่อ sequence จึงอาจเป็น noise.
