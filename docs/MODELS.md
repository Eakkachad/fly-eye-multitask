# แบบจำลอง (Models)

ทุกโมเดลรับ input เดียวกัน `lum` รูป (B, T, 1, 721) และคืน `flow` (B, T, 2, 721) กับ `depth` (B, T, 1, 721)
ใช้ loss เดียวกัน (l2norm ของ flyvis ต่อแต่ละงาน ถ่วงน้ำหนักเท่ากัน), optimizer Adam, lr schedule, batch size 4 และจำนวน iteration **เท่ากันทุกโมเดล** (`train.py`)

## M1 — Connectome model (flyvis, wiring จริง)
- **ที่มา:** โครงข่ายประสาทระบบการมองเห็นของแมลงหวี่ (Lappalainen et al. 2024) สร้างจาก connectome
  - **45,669 เซลล์** แบ่งเป็น **65 ชนิด** วางบนตาข่ายหกเหลี่ยม
  - มีการเชื่อมต่อ 1.5 ล้านเส้น จัดเป็น **604 คู่ชนิดเซลล์** แต่ละคู่มี "kernel เชิงพื้นที่" (ออฟเซ็ต du, dv และจำนวน synapse) กับเครื่องหมาย (กระตุ้นหรือยับยั้ง)
- **Dynamics:** แต่ละเซลล์เป็นสมการเชิงอนุพันธ์ (leaky integrator) ที่วิวัฒน์ไปตามเวลา จึงเป็น **recurrent network โดยธรรมชาติ**
- **สิ่งที่ train ได้:** แค่ 734 พารามิเตอร์ในตัวโครงข่าย ได้แก่ bias และ time constant ต่อชนิดเซลล์ และ strength ต่อคู่ชนิด ส่วน wiring ถูก connectome กำหนดไว้ทั้งหมด
- **Decoder:** อ่านค่าจากเซลล์ปลายทาง แล้วผ่าน decoder แบบ convolution (DecoderGAVP ของ flyvis) แยกสำหรับ flow และ depth รวม 14,653 พารามิเตอร์
- **รวม 15,387 พารามิเตอร์**

## M2 — Null แบบ degree-preserving (สลับสาย)
- เหมือน M1 ทุกอย่าง แต่สลับ "ปลายทาง" ของการเชื่อมต่อ 604 คู่ด้วยวิธี **Maslov–Sneppen**
- **สิ่งที่คงไว้:**
  - จำนวนเส้นเข้าและออกของทุกชนิดเซลล์ (degree)
  - เครื่องหมายของแต่ละเส้น (Dale's law: เครื่องหมายผูกกับชนิดเซลล์ต้นทาง)
  - kernel เชิงพื้นที่ (ติดไปกับเส้น)
- **สิ่งที่เปลี่ยน:** "ใครต่อกับใคร"
- **คำถามที่ตอบ:** ถ้า M1 ชนะ M2 แปลว่า**รูปแบบการเชื่อมต่อจริง**ช่วย ไม่ใช่แค่สถิติของกราฟ
- **ข้อสังเกต:** connectome จริงมี self-loop ภายในชนิดเดียวกัน 23 เส้น แต่ M2 ไม่มี

## M3 — Null แบบสุ่ม (Erdős–Rényi ระดับชนิดเซลล์)
- สุ่มคู่ชนิดเซลล์ 604 คู่ใหม่ทั้งหมด จำนวนเส้นเท่าเดิม และสัดส่วนกระตุ้นต่อยับยั้งเท่าเดิม (376 : 228)
- ไม่มีเส้นใดเข้าสู่ photoreceptor (R1–R8)
- เป็นเส้นฐานล่างสุดของ "โมเดลที่มีโครงสร้างแบบ flyvis แต่ wiring ไร้ความหมาย"

## M4 — HexConvGRU ขนาดเล็ก (พารามิเตอร์เท่า M1)
- **โครงสร้าง:** deep learning มาตรฐานสำหรับวิดีโอ
  - **HexConv:** convolution บนตาข่ายหกเหลี่ยม ใช้เพื่อนบ้าน 7 จุด (ตัวเอง + 6 ทิศ) ขอบใช้ zero padding
  - ตามด้วย **ConvGRU** ที่จำสถานะข้ามเฟรม
  - แล้วแยกเป็น 2 head สำหรับ flow และ depth
- **ขนาด:** `make_small_matched()` มี **15,402 พารามิเตอร์** ต่างจาก M1 แค่ +0.1%
- **คำถามที่ตอบ:** ที่งบพารามิเตอร์เท่ากัน โครงสร้างจากชีววิทยาดีกว่าโครงสร้างที่มนุษย์ออกแบบไหม

## M5 — HexConvGRU ขนาดใหญ่
- `make_large()` มี **604,835 พารามิเตอร์** มากกว่า M1 ประมาณ 40 เท่า
- **คำถามที่ตอบ:** ถ้าเพิ่ม compute และพารามิเตอร์ให้ deep learning ทั่วไป มันจะชนะ prior จาก connectome ไหม และต้องใช้ข้อมูลมากกว่าเท่าไร

## M6 / M7 — Hybrid: front-end connectome + HexConvGRU (PLAN A5; H4, H5)
- **M6:** โครงข่าย flyvis ที่ใช้ connectome จริง (เหมือน M1 รวม activity penalty) → activity ที่ผ่าน rectifier ของเซลล์ชนิดปลายทางบนทั้ง 721 hexal → trunk HexConvGRU ที่ใช้ร่วมกัน → head ของ flow และ depth
- **M7:** เหมือน M6 แต่ใช้ connectome แบบ rewired ของ M2 (control ที่แยก "wiring จริง" ออกจาก "front-end แบบ recurrent ที่เพิ่มเข้ามา")
- **ขนาด:** 15,423 พารามิเตอร์ (ใกล้ M1/M4)
- **H4:** M6 ชนะ M4 · **H5:** M6 ชนะ M7 ครบ 3/3 seed ถ้า H4 ผ่านแต่ H5 ไม่ผ่าน แปลว่าประโยชน์มาจากสถาปัตยกรรม ไม่ใช่ wiring
- **หมายเหตุ:** เพิ่มหลังเห็นผล probe (post-probe, pre-grid) ระบุไว้ใน PLAN A5

## M6f / M7f — Frozen front-end + residual (PLAN A6.2; H7)
- front-end = checkpoint ที่ train แล้วของ M1 (M6f) หรือ M2 (M7f) ใน seed เดียวกัน **freeze** ทั้งโครงข่ายและ decoder
- output = output ของ decoder ที่ freeze + residual จาก trunk HexConvGRU ที่ layer สุดท้าย **zero-init** จึงเริ่ม train ที่คำตอบของ M1/M2 พอดี
- **train ได้ 14,689 พารามิเตอร์** รายงานทั้ง front-end อย่างเดียวและผลสุดท้าย · **H7:** M6f ชนะ M7f บน test flow EPE ครบ 3/3 seed
- ต้อง train หลัง M1/M2 ของ grid (ใช้ `--frontend-ckpt runs/<m1|m2 run>/best.pt`)

## M8 — HexConvGRU-K (PLAN A6.3; H6)
- สถาปัตยกรรม/พารามิเตอร์แบบ M4 (**15,402**) แต่วน GRU cell K ครั้งต่อเฟรม โดยใช้ weight ร่วมกันและป้อน input จาก encoder ซ้ำ
- train ด้วย K ~ U{1..4} (`--k-max 4`) ประเมินที่ K = 1..4 เป็นกราฟ any-time (`eval.py --k K`) ค่าหลักคือ K = 4
- **H6:** M8 (K=4) ชนะ M4 บน test flow EPE อย่างน้อย 2/3 seed
- ไอเดียของ M6f/M7f/M8 มาจากบันทึกวิธีวิจัยของกลุ่มและงานตีพิมพ์ที่อ้างอิงใน PLAN A6

## (อ้างอิง) M0 — flyvis pretrained
- เป็นโมเดลที่ทีมผู้พัฒนา flyvis train มาแล้ว (250k iteration, flow อย่างเดียว) **ไม่ได้ train โดยเรา** ใช้เป็นแค่ค่าอ้างอิงของ flow
- **ข้อจำกัด:** เคยเห็นฉากทดสอบบางฉากแล้ว (ดู [DATA.md](DATA.md))
